# dedup_tool

**Один Bash-скрипт для больших словарей.** Он чистит словарь — кодировки, кракозябры, невидимый мусор, фильтры длины и цифр — и убирает из него все строки, которые уже есть в ваших эталонных файлах. Всё за один проход, с меню, по-русски или по-английски.

Обычный случай: вы собираете словари паролей или логинов из разных источников и хотите, чтобы в каждом новом остались только строки, которых у вас ещё нет.

[English version](README.md)

## Что умеет

- **Один проход без промежуточных файлов.** Подготовка → `sort -u` → `comm -13` с каждым эталоном → `<имя>_final.txt`. На диск пишется только итог, плюс временные файлы самого `sort`, если данные не влезли в память.
- **Подготовка.** Каждый шаг — вопрос с разумным вариантом по умолчанию, а перед ним — сколько таких строк и примеры:
  - UTF-16 → UTF-8 (по BOM или по нулевым байтам);
  - однобайтовую кириллицу (Windows-1251, KOI8-R, CP866) узнаёт сам; смешанный файл переводит построчно, а строки в UTF-8 не трогает;
  - CRLF и BOM, в том числе невидимый U+FEFF внутри строк;
  - слова в UTF-16 посреди файла в UTF-8 (после каждой буквы NUL);
  - кракозябры: UTF-8, прочитанный как Windows-1252 или Latin-1 («Ð¿Ð°Ñ€Ð¾Ð»ÑŒ» → «пароль»), русский текст из DOS, прочитанный как Windows-1251 («ЏаЁўҐв» → «Привет»), UTF-8, прочитанный как Windows-1251 («РџСЂРёРІРµС‚» → «Привет»);
  - неверный UTF-8, символ-заменитель U+FFFD, управляющие символы;
  - фильтры длины и строк из одних цифр; убранные короткие строки и строки из цифр можно сохранить в `<имя>_short.txt` и `<имя>_digits.txt`.
- **Эталоны** лежат в `Compare Files/`. Каждый файл — одно «поколение» сравнения, по порядку имён. Скрипт их проверяет (CRLF/BOM, порядок, дубли) и исправляет только с вашего согласия.
- **Очередь.** Несколько словарей подряд: каждый чистится от эталонов и от итогов всех предыдущих, так что итоги не пересекаются.
- **Объединение** итогов в один файл, **деление** файла на части.
- **WSL.** Если файлы лежат на диске Windows (`/mnt/c`, `/mnt/d`), скрипт предложит работать во временной папке Linux: построчная запись через мост WSL в сотни раз медленнее.
- Прогресс на долгих шагах, лог каждого действия, статистика по шагам. Ещё скрипт замечает архив, переименованный в `.txt`, рабочий файл — копию эталона и строки итога с пробелами по краям.

## Что нужно

- Bash 4.2 или новее (лучше 5.x), GNU coreutils (`sort`, `comm`, `split`, `stat`, `mkfifo`, `df`, `od`), GNU `grep` с `-P`, GNU `sed`, `awk`, `iconv`.
- Работает в **Git for Windows** (Git Bash), **WSL** и **Linux**. На macOS не проверялся; там нужны GNU-версии (`brew install coreutils grep gnu-sed`).

## Установка

```bash
git clone https://github.com/edik44/dedup_tool.git
cd dedup_tool
chmod +x dedup_tool.sh
```

Или скачайте только `dedup_tool.sh` и положите рядом со словарями.

## Как пользоваться

Положите словари (`*.txt`) рядом со скриптом, а эталоны — в папку `Compare Files/`:

```
ваша_папка/
├── dedup_tool.sh
├── new_words.txt            ← рабочие файлы
├── more_words.txt
└── Compare Files/
    ├── 01_base.txt          ← эталоны, каждый — поколение
    └── 02_other_base.txt
```

Запустите `./dedup_tool.sh` (в Windows можно и двойным нажатием на файл в Проводнике) и выберите пункт:

```
  1) Полная обработка: подготовка и сравнение с эталонами → <имя>_final.txt
  2) Только подготовка (кодировка, CRLF/BOM, фильтры) → <имя>_prep.txt
  3) Только сравнение с эталонами, файл как есть → <имя>_final.txt
  4) Несколько словарей по очереди: каждый чистится и от предыдущих → _final у каждого
  5) Объединить итоги _final в один файл → merged.txt и список файлов merged_list.txt
  6) Разделить готовый файл на части
  7) Справка
  8) Язык / Language: русский
  0) Выход
```

Ваши рабочие файлы скрипт не меняет; после очереди переносит их в `originals_<дата-время>/`. Эталоны исправляются только после вопроса.

### Без меню

```bash
./dedup_tool.sh full words.txt
./dedup_tool.sh clean words.txt
./dedup_tool.sh compare [file...]
./dedup_tool.sh queue a.txt b.txt c.txt
./dedup_tool.sh merge [file...]
./dedup_tool.sh split words.txt 4
```

`split` принимает и размер части: `500M`, `2G`. Ответы на вопросы можно подать через stdin, например `printf 'y\nn\nn\n' | ./dedup_tool.sh full raw.txt`; с `</dev/null` у каждого вопроса будет вариант по умолчанию.

### Язык

Язык интерфейса выбирается по языку системы, в Git Bash и WSL — по языку Windows. Сменить его можно пунктом 8 меню (выбор запоминается), ключом `--lang ru` или `--lang en` или переменной `DEDUP_LANG=ru`.

## Как это выглядит

Числа ниже придуманы:

```
=== Один проход до итога ===
Шаги: iconv (WINDOWS-1251 → UTF-8) → CRLF/BOM → проверка UTF-8 → управляющие символы → длина 8–18 → сортировка (память до 3,2 ГБ) → эталон base.txt → words_final.txt
Строк на входе: 2 500 000
  − нечитаемые (не UTF-8 или U+FFFD): 0
  − с управляющими символами: 12
  − длина вне 8–18: 840 210
  − повторы внутри файла: 3 904
  − есть в эталоне base.txt (поколение 1): 1 402 551
▐► Обработано поколений: 1 из 1
✔ Финальный файл: words_final.txt — строк: 253 323, 5 МБ (2,1 с)
```

Итог после перевода из Windows-1251 бывает больше исходника: в UTF-8 русская буква занимает 2 байта, а не 1. Скрипт об этом скажет.

## Большие файлы

- **Память.** `sort` берёт до половины свободной памяти и до 8 потоков; что не влезло, уходит в его временные файлы рядом с итогом. В WSL остальное занимает кэш файлов Linux, поэтому WSL в диспетчере задач почти на пределе — это нормально. `wsl --shutdown` вернёт память после работы.
- **Диск.** В WSL словарь на 6,5 ГБ с эталоном на 8,1 ГБ — по оценке около 70 ГБ записи в первый раз (копии в папку Linux и обратно, сортировка эталона, временные файлы `sort`, итог) и около 40 ГБ потом. Свободного места нужно примерно втрое больше словарей и эталонов вместе. Держите большие файлы прямо в Linux (в Проводнике — `\\wsl.localhost\<дистрибутив>\home\<пользователь>`): тогда копировать ничего не нужно.
- **HDD.** Работать будет, но медленнее — особенно копирование, если словари и диск Linux на одном HDD, и сортировка больших файлов. Если есть SSD, держите на нём диск Linux (`ext4.vhdx`) и рабочую папку.

## Чем отличается от других инструментов

Главную работу — убрать строки, которые есть в других файлах, — делают и [rling](https://github.com/Cynosureprime/rling), и `rli`/`rli2` из [hashcat-utils](https://github.com/hashcat/hashcat-utils); [duplicut](https://github.com/nil0x42/duplicut) убирает повторы без сортировки. Это быстрые инструменты с ключами командной строки. dedup_tool — про всё вокруг этой работы: подготовку перед сравнением (кодировки, кракозябры, невидимый мусор, слова из UTF-16), поколения и очереди, WSL и логи — с меню и вопросами вместо ключей.
