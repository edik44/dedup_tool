# dedup_tool

**Один Bash-скрипт для больших словарей.** Он чистит словарь — кодировки, кракозябры, невидимый мусор, фильтры длины и цифр — и убирает из него все строки, которые уже есть в ваших эталонных файлах. Всё за один проход, с меню, по-русски или по-английски.

Обычный случай: вы собираете словари паролей или логинов из разных источников и хотите, чтобы в каждом новом остались только строки, которых у вас ещё нет.

## Что умеет

- **Один проход без промежуточных файлов.** Подготовка → `sort -u` → `comm -13` с каждым эталоном → `<имя>_final.txt`. На диск пишется только итог, плюс временные файлы самого `sort`, если данные не влезли в память.
- **Подготовка.** Каждый шаг — вопрос с разумным вариантом по умолчанию, а перед ним — сколько таких строк и примеры:
  - UTF-16 → UTF-8 (по BOM или по нулевым байтам);
  - однобайтовую кириллицу (Windows-1251, KOI8-R, CP866) узнаёт сам; смешанный файл переводит построчно, а строки в UTF-8 не трогает;
  - CRLF и BOM, в том числе невидимый U+FEFF внутри строк;
  - символ CR внутри строки: редакторы показывают его как перенос, и одна строка выглядит как две; такие строки разбиваются;
  - слова в UTF-16 посреди файла в UTF-8 (после каждой буквы NUL);
  - кракозябры: UTF-8, прочитанный как Windows-1252 или Latin-1 («Ð¿Ð°Ñ€Ð¾Ð»ÑŒ» → «пароль»), русский текст из DOS, прочитанный как Windows-1251 («ЏаЁўҐв» → «Привет»), UTF-8, прочитанный как Windows-1251 («РџСЂРёРІРµС‚» → «Привет», «cafГ©» → «café»), русский текст в KOI8-R, прочитанный как Windows-1251 («РТЙЧЕФ» → «привет»), русский текст из DOS без старшего бита (буква «а» стала пробелом, другие буквы — знаками);
  - неверный UTF-8, символ-заменитель U+FFFD, управляющие символы;
  - пустые строки и строки из одних пробелов или табов;
  - фильтры длины и строк из одних цифр; убранные короткие строки, строки из цифр и строки не в UTF-8 можно сохранить в `<имя>_short.txt`, `<имя>_digits.txt` и `<имя>_notutf8.txt`.
- **Эталоны** лежат в `Compare Files/`. Каждый файл — одно «поколение» сравнения, по порядку имён. Скрипт их проверяет (CRLF/BOM, порядок, дубли) и исправляет только с вашего согласия.
- **Очередь.** Несколько словарей подряд: каждый чистится от эталонов и от итогов всех предыдущих, так что итоги не пересекаются. Меню показывает файлы от большого к меньшему: достаточно нажать Enter, а порядок можно задать и самому.
- **Объединение** итогов в один файл, **деление** файла на части.
- **Работа со словарями** (пункт 7 меню): почта → логины, `user:pass`, любой разделитель, почта, ссылки и IP из дампа, раскладка RU ↔ EN, регистр, пробелы, отбор строк по куску, разложить по алфавитам, самые частые строки, повторы без сортировки, поиск по словарям, пробелы по краям строк, убрать строки других словарей.
- **WSL.** Если файлы лежат на диске Windows (`/mnt/c`, `/mnt/d`), скрипт предложит работать во временной папке Linux: построчная запись через мост WSL в сотни раз медленнее.
- Прогресс на долгих шагах, лог каждого действия, статистика по шагам. Ещё скрипт замечает архив, переименованный в `.txt`, рабочий файл — копию эталона и строки итога с пробелами по краям.

## Что нужно

- Bash 4.2 или новее (лучше 5.x), GNU coreutils (`sort`, `comm`, `split`, `stat`, `mkfifo`, `df`, `od`), GNU `grep` с `-P`, GNU `sed`, `awk`, `iconv`.
- Работает в **Git for Windows** (Git Bash), **WSL** и **Linux**. На macOS не проверялся; там нужны GNU-версии (`brew install coreutils grep gnu-sed`).
- В Windows нужен [Git for Windows](https://git-scm.com/download/win) (бесплатный): в нём bash и эти утилиты. `dedup_tool_first_windows_start.bat` сам проверит, есть ли он, и предложит установить.

## Установка

### Windows

1. Скачайте `dedup_tool.sh` и `dedup_tool_first_windows_start.bat` со страницы [последнего выпуска](https://github.com/edik44/dedup_tool/releases/latest) и положите оба в папку со словарями.
2. Дважды нажмите `dedup_tool_first_windows_start.bat`. Он проверит, есть ли Git for Windows, а если нет — предложит поставить его через winget (Windows спросит разрешение администратора) или открыть страницу загрузки. Потом в этой папке откроется меню.
3. Дальше `.bat` не нужен: дважды нажимайте сам `dedup_tool.sh` — Git for Windows открывает файлы `.sh` в Git Bash. `.bat` можно удалить или оставить: он работает и потом.
4. Windows может предупредить, что файл скачан из интернета, — разрешите запуск (SmartScreen: «Подробнее» → «Выполнить в любом случае»).

### Linux, WSL, Git Bash

```bash
git clone https://github.com/edik44/dedup_tool.git
cd dedup_tool
chmod +x dedup_tool.sh
./dedup_tool.sh --help
```

В Linux и WSL `./` перед именем обязателен: текущей папки нет в `PATH`, и без него будет `command not found`.

Или скачайте только `dedup_tool.sh` и положите рядом со словарями.

## Как пользоваться

Положите словари (`*.txt`) рядом со скриптом, а эталоны — в папку `Compare Files/`:

```
ваша_папка/
├── dedup_tool.sh
├── dedup_tool_first_windows_start.bat  ← первый запуск в Windows
├── new_words.txt            ← рабочие файлы
├── more_words.txt
└── Compare Files/
    ├── 01_base.txt          ← эталоны, каждый — поколение
    └── 02_other_base.txt
```

Запустите `./dedup_tool.sh` (в Windows — двойным нажатием на него, а в самый первый раз — на `dedup_tool_first_windows_start.bat`) и выберите пункт:

```
  1) Полная обработка: подготовка и сравнение с эталонами → <имя>_final.txt
  2) Только подготовка (кодировка, CRLF/BOM, фильтры) → <имя>_prep.txt
  3) Только сравнение с эталонами, файл как есть → <имя>_final.txt
  4) Несколько словарей по очереди: каждый чистится и от предыдущих → _final у каждого
  5) Объединить итоги _final в один файл → merged.txt и список файлов merged_list.txt
  6) Разделить готовый файл на части
  7) Работа со словарями: логины, раскладка, регистр, алфавиты, поиск…
  8) Язык / Language: русский
  9) Справка
  0) Выход
```

Ваши рабочие файлы скрипт не меняет, кроме утилиты 14, если попросить заменить файл; после очереди переносит их в `originals_<дата-время>/`. Эталоны исправляются только после вопроса.

### Без меню

```bash
./dedup_tool.sh full words.txt
./dedup_tool.sh clean words.txt
./dedup_tool.sh compare [file...]
./dedup_tool.sh queue a.txt b.txt c.txt
./dedup_tool.sh merge [file...]
./dedup_tool.sh split words.txt 4
```

`split` принимает и размер части: `500M`, `2G`. Ответы на вопросы можно подать через stdin, например `printf 'y\nn\nn\n' | ./dedup_tool.sh full raw.txt`; с `</dev/null` у каждого вопроса будет вариант по умолчанию.

### Работа со словарями

Пункт 7 меню. Исходный файл не меняется (кроме утилиты 14, если попросить), результат — новый файл `<имя>_<что>.txt` (имя занято — `_2`). Логины, пароли, части строк и адреса — без повторов и по порядку байтов; остальное — строка в строку, в прежнем порядке. После утилит 1–4 можно сохранить словарь без строк, из которых что-то извлечено: строка убирается целиком, файл `_rest`.

| № | Что делает | Результат |
|---|---|---|
| 1 | Почта → логины: часть до `@` | `_logins` |
| 2 | `user:pass` → логины и пароли, по первому `:` или `;` | `_logins`, `_passwords` |
| 3 | Любой разделитель (`:` `/` `;` `---` `(at)`): левая и правая часть | `_left`, `_right` |
| 4 | Вырезать из дампа почту, ссылки и адреса IP | `_emails`, `_urls`, `_ip` |
| 5 | Раскладка: `привет` → `ghbdtn` и обратно | `_en`, `_ru` |
| 6 | Регистр: все маленькие, все большие, первая большая или маленькая, или все четыре файла сразу | `_lower`, `_upper`, `_cap`, `_uncap` |
| 7 | Строки с пробелом: убрать или оставить только первое слово | `_nospace`, `_firstword` |
| 8 | Обрезать пробелы и табы по краям, сдвоенные внутри — в один | `_trim` |
| 9 | Убрать строки с заданными кусками (`- _ admin`) | `_filtered` |
| 10 | Разложить по алфавитам; несколько алфавитов в строке — `_mixed` | `_latin`, `_cyr`, `_greek`, `_hebrew`, `_arabic`, `_cjk`, `_other`, `_mixed` |
| 11 | Самые частые строки: сколько раз, для нескольких файлов — и в скольких | `_top` |
| 12 | Убрать повторы без сортировки, порядок строк прежний | `_uniq` |
| 13 | Найти строку в словарях папки и в эталонах: где и сколько раз | экран и лог |
| 14 | Пробелы и табы по краям: вынести такие строки, обрезать справа или слева; можно заменить сам файл, если попросить | `_edge`, `_noedge`, `_rtrim`, `_ltrim` |
| 15 | Убрать из файла строки других словарей (без `Compare Files`), отсортировано и без повторов | `_minus` |

Без меню:

```bash
./dedup_tool.sh tool logins words.txt
./dedup_tool.sh tool userpass dump.txt
./dedup_tool.sh tool cut dump.txt '---' left
./dedup_tool.sh tool extract dump.txt emails ip
./dedup_tool.sh tool layout words.txt ru2en
./dedup_tool.sh tool case words.txt lower
./dedup_tool.sh tool spaces words.txt first
./dedup_tool.sh tool trim words.txt
./dedup_tool.sh tool filter words.txt - _ admin
./dedup_tool.sh tool alphabets words.txt
./dedup_tool.sh tool top 100 a.txt b.txt
./dedup_tool.sh tool uniq words.txt
./dedup_tool.sh tool find secret
./dedup_tool.sh tool edge words.txt right
./dedup_tool.sh tool minus words.txt other.txt more.txt
```

### Язык

Язык интерфейса выбирается по языку системы, в Git Bash и WSL — по языку Windows. Сменить его можно пунктом 8 меню (выбор запоминается), ключом `--lang ru` или `--lang en` или переменной `DEDUP_LANG=ru`.

## Как это выглядит

Числа ниже придуманы:

```
=== Один проход до итога ===
Шаги: iconv (WINDOWS-1251 → UTF-8) → CRLF/BOM → проверка UTF-8 → управляющие символы → длина 8–18 → сортировка (память до 3,2 ГБ) → эталон base.txt → words_final.txt
Строк на входе: 2 500 000
  − нечитаемые (не UTF-8 или U+FFFD): 0
  − с управляющими символами: 12
  − длина вне 8–18: 840 210
  − повторы внутри файла: 3 904
  − есть в эталоне base.txt (поколение 1): 1 402 551
▐► Обработано поколений: 1 из 1
✔ Финальный файл: words_final.txt — строк: 253 323, 5 МБ (2,1 с)
```

Итог после перевода из Windows-1251 бывает больше исходника: в UTF-8 русская буква занимает 2 байта, а не 1. Скрипт об этом скажет.

## Большие файлы

- **Git Bash или WSL.** Словари примерно до 1 ГБ удобно обрабатывать и в Git Bash, прямо в Windows (это зависит от ПК). С большими лучше WSL: там та же работа идёт в 3–4 раза быстрее (замер на 1.2.19: словарь 95 МБ и эталон 48 МБ — 12 с в Git Bash, 3,5 с в WSL).
- **Память.** `sort` берёт до половины свободной памяти и до 8 потоков; что не влезло, уходит в его временные файлы рядом с итогом. В WSL остальное занимает кэш файлов Linux, поэтому WSL в диспетчере задач почти на пределе — это нормально. `wsl --shutdown` вернёт память после работы.
- **Диск.** В WSL словарь на 6,5 ГБ с эталоном на 8,1 ГБ — по оценке около 70 ГБ записи в первый раз (копии в папку Linux и обратно, сортировка эталона, временные файлы `sort`, итог) и около 40 ГБ потом. Свободного места нужно примерно втрое больше словарей и эталонов вместе. Держите большие файлы прямо в Linux (в Проводнике — `\\wsl.localhost\<дистрибутив>\home\<пользователь>`): тогда копировать ничего не нужно.
- **HDD.** Работать будет, но медленнее — особенно копирование, если словари и диск Linux на одном HDD, и сортировка больших файлов. Если есть SSD, держите на нём диск Linux (`ext4.vhdx`) и рабочую папку.

## Чем отличается от других инструментов

Главную работу — убрать строки, которые есть в других файлах, — делают и [rling](https://github.com/Cynosureprime/rling), и `rli`/`rli2` из [hashcat-utils](https://github.com/hashcat/hashcat-utils); [duplicut](https://github.com/nil0x42/duplicut) убирает повторы без сортировки. Это быстрые инструменты с ключами командной строки. dedup_tool — про всё вокруг этой работы: подготовку перед сравнением (кодировки, кракозябры, невидимый мусор, слова из UTF-16), поколения и очереди, WSL и логи — с меню и вопросами вместо ключей.
